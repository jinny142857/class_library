# 우리 반 도서관

초등학교 학급 문고용 대출·반납·예약 웹앱입니다. 학생은 개인 QR 카드로 로그인해 책 QR을 찍어 스스로 빌리고 반납하며, 교사는 관리자 화면에서 도서·학생·대출·예약·학사일정·통계를 관리합니다.

- **설치할 패키지 없음.** Node.js 하나만 있으면 `node server.js`로 실행됩니다.
- 데이터는 서버의 SQLite 파일(`data/library.db`) 하나에 저장되고, 매일 자동 백업됩니다.

## 1. 실행하기

1. [Node.js](https://nodejs.org) **22.13 이상**(LTS 권장)을 설치합니다.
2. 이 폴더에서 실행합니다.
   ```
   npm start
   ```
   (또는 `node --disable-warning=ExperimentalWarning server.js`)
3. 브라우저에서 엽니다.
   - 학생 화면: `http://localhost:3000`
   - 교사 화면: `http://localhost:3000/admin` → 처음 접속하면 관리자 계정을 만듭니다.

## 2. 처음 사용 순서

1. **학생** 메뉴 → 「명단 한 번에 등록」: 엑셀에서 `번호, 이름` 두 칸을 복사해 붙여 넣거나 CSV 파일을 고릅니다.
2. 「전체 QR 카드 인쇄」 → 인쇄 창에서 **PDF로 저장** 또는 바로 인쇄 (A4 한 장에 12명).
3. **도서** 메뉴 → 「도서 등록」: ISBN을 입력하거나 「스캔」으로 바코드를 찍고 「조회」하면 제목·저자·표지가 채워집니다. 같은 책이 여러 권이면 권수를 늘립니다.
4. 「선택 QR 인쇄」로 책 라벨(A4 한 장 21개 또는 40개)을 뽑아 책에 붙입니다.
   책에 이미 바코드(등록번호) 라벨이 있다면 소장본의 「코드 변경」에 그 번호를 넣으면 기존 바코드로도 인식됩니다.
5. **학사일정** 메뉴: 학교 재량휴업일·개교기념일 등을 날짜를 눌러 휴업일로 지정합니다. (2026~2027년 법정 공휴일·대체공휴일은 미리 들어 있습니다)
6. 교실 태블릿/PC에서 학생 화면을 열어 둡니다.

## 3. 카메라와 HTTPS (중요)

브라우저는 **보안 연결(https)** 이나 **localhost**에서만 카메라를 허용합니다.

| 사용 방식 | 필요한 것 |
|---|---|
| 서버를 돌리는 그 PC에서 학생 화면을 쓴다 | 그대로 됨 (`http://localhost:3000`) |
| 교실 태블릿 등 다른 기기에서 접속한다 | HTTPS 주소가 필요 |

HTTPS로 여는 방법(택1):
- **클라우드 배포(추천)**: Railway, Fly.io 등 Node.js를 지원하고 **영구 저장소(volume)** 를 붙일 수 있는 곳에 올리고 `DATA_DIR`을 그 저장소 경로로 지정합니다. (영구 저장소가 없는 무료 호스팅은 재시작 시 데이터가 사라지므로 쓰면 안 됩니다) 아래 3-1에 Railway 기준 단계별 안내가 있습니다.
- **교실 PC + 터널**: PC에서 서버를 실행하고 Cloudflare Tunnel 같은 도구로 https 주소를 만듭니다.
- **인증서 직접 지정**: `TLS_CERT`, `TLS_KEY` 환경변수에 인증서 파일 경로를 주면 서버가 직접 https로 열립니다.

### 3-1. Railway로 배포하기

교실 PC를 계속 켜 둘 필요 없이, 작은 비용(또는 무료 체험)으로 24시간 켜진 서버를 둘 수 있습니다. 태블릿과 선생님 PC는 그냥 이 서버의 https 주소에 접속하는 "손님"이 됩니다.

1. [railway.app](https://railway.app)에서 GitHub 계정으로 가입합니다.
2. **New Project** → **Deploy from GitHub repo** → 이 저장소(`class_library`)를 선택합니다. (처음이면 Railway의 GitHub App에 저장소 접근 권한을 허용해야 합니다)
3. 자동으로 Node.js 프로젝트로 인식되어 `npm start`로 빌드·실행됩니다(이 저장소의 `railway.json`에 설정돼 있음). 외부 패키지가 없어 빌드도 빠릅니다.
4. **데이터가 재배포 시 사라지지 않도록 Volume을 반드시 추가**합니다: 서비스 → **Settings** → **Volumes** → **New Volume** → 마운트 경로를 `/data`로 지정합니다.
5. **Variables**(환경변수) 탭에서 추가합니다:
   - `DATA_DIR` = `/data` (4번에서 만든 볼륨 경로와 일치해야 합니다)
   - `ADMIN_USERNAME`, `ADMIN_PASSWORD` (선택) — 지정하면 첫 배포 때 관리자 계정이 자동으로 만들어집니다. 비워 두면 배포 후 `/admin`에 처음 접속할 때 화면에서 만들 수 있습니다.
6. **Settings** → **Networking** → **Generate Domain**을 눌러 공개 https 주소를 받습니다 (예: `class-library-production.up.railway.app`). Railway가 TLS(https)를 자동으로 처리하므로 `TLS_CERT`/`TLS_KEY`는 설정하지 않습니다.
7. 배포가 끝나면 그 주소로 접속해 평소처럼 사용합니다. 태블릿은 `https://그주소/`, 선생님은 `https://그주소/admin`.
8. 이후 `git push`로 코드를 올릴 때마다 Railway가 자동으로 재배포합니다. 데이터는 Volume에 남아 있으므로 책·학생·대출 기록은 그대로 유지됩니다.

**스캔 방식** (자동으로 선택됨)
1. 브라우저 내장 바코드 인식(BarcodeDetector) — Android 태블릿 Chrome, 크롬북 등
2. 내장 인식이 없는 브라우저(예: Windows Chrome)는 함께 들어 있는 `html5-qrcode` 라이브러리로 인식
3. **USB 바코드 스캐너**: 그냥 꽂아서 찍으면 됩니다(키보드 입력으로 인식)
4. 화면 아래 입력칸에 코드 직접 입력

공용 태블릿은 학생이 화면 앞에서 카드를 보여 주기 쉽도록 기본으로 **앞면 카메라**를 씁니다. 화면의 「카메라 바꾸기」로 바꿀 수 있고 기기에 기억됩니다.

## 4. 운영 규칙 (PRD 기준, 설정에서 변경 가능)

| 항목 | 기본값 |
|---|---|
| 1인당 대출 | 1권 |
| 대출 기간 | 3수업일 (대출 당일 제외, 예: 수요일 대출 → 월요일 반납) |
| 연장 | 예약자가 없을 때 1회, 2수업일 |
| 예약 | 학생당 1권, 도서(제목) 단위, 신청 순서대로 |
| 예약 우선권 | 반납 다음 수업일 하루 (예: 금요일 반납 → 월요일까지) |
| 연체 | 반납 예정일 다음 수업일부터 1일씩, 수업일에만 증가 |
| 이용 정지 | 연체 수업일수 × 1배, 반납 다음 수업일부터 |
| 자동 로그아웃 | 90초 동안 사용하지 않으면 (15초 전에 안내) |

수업일 = 토·일, 법정 공휴일·대체공휴일, 교사가 지정한 휴업일을 뺀 날. 교사가 지정한 날짜가 공휴일보다 우선합니다(예: 토요 수업일 지정).

## 5. PRD 12장 「추후 결정 사항」에 대해 정한 기본값

| # | 항목 | 정한 내용 |
|---|---|---|
| 1 | 명단 일괄 등록 형식 | CSV 파일 또는 엑셀/구글 시트에서 **복사·붙여넣기**(탭 구분). `번호,이름` 또는 `이름`만. 머리글 줄은 자동으로 건너뜀. 한글 윈도우 엑셀 CSV(EUC-KR)도 인식 |
| 2 | ISBN 조회처 | 국립중앙도서관 → 카카오 → Google Books 순서로 시도. 앞의 두 곳은 API 키가 있을 때만 사용 (키 없이도 Google Books로 동작) |
| 3 | QR 라벨 규격 | A4. 학생 카드 3×4(12장), 책 라벨 크게 3×7(21개, QR 32mm) / 작게 4×10(40개, QR 23mm). 브라우저 인쇄 창에서 PDF로 저장 |
| 4 | 자동 로그아웃 | 90초 (설정에서 변경) |
| 5 | 관리자 계정 | 여러 명 가능, 권한은 모두 동일 |
| 6 | 학사일정 변경 시 기존 대출 | **자동으로 바꾸지 않음.** 다시 계산한 날짜가 달라지는 대출·우선권을 학사일정 화면 위에 목록으로 보여 주고, 교사가 골라서 반영 (기록 남음) |
| 7 | 이용 정지 기간 | 반납하는 순간부터 막히고, **반납 다음 수업일부터 N수업일째 날 끝**에 풀림. 학생 화면에 「○월 ○일(요일)까지 쉬는 기간」으로 표시 |

그 밖에 정한 것:
- 연장은 반납 예정일 **당일까지** 신청 가능합니다(지나면 불가).
- 연체 중(반납 안 함)인 학생도 신규 대출·예약이 막힙니다.
- 예약은 책꽂이에 빌릴 수 있는 같은 책이 없을 때만 가능합니다(있으면 「바로 빌릴 수 있어요」 안내).
- 공용 기기 정책: 새 학생이 로그인하면 이전 학생 세션은 끝납니다.
- 우선권 만료·승계는 5분마다, 그리고 대출·예약 요청 때마다 서버가 즉시 다시 판정합니다. 며칠간 아무도 접속하지 않아도 만료일 기준으로 차례대로 계산되어 결과가 같습니다.

## 6. 환경변수 (모두 선택)

| 변수 | 설명 |
|---|---|
| `PORT` | 포트 (기본 3000) |
| `DATA_DIR` | 데이터 폴더 (기본 `./data`) |
| `TLS_CERT`, `TLS_KEY` | HTTPS 인증서·키 파일 경로 |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | 첫 실행 시 관리자 계정 자동 생성 |
| `NL_API_KEY` | 국립중앙도서관 ISBN 서지정보 API 키 |
| `KAKAO_REST_API_KEY` | 카카오 REST API 키 (책 검색) |
| `HOLIDAY_API_KEY` | 공공데이터포털 특일정보 API 키 (학사일정에 「공휴일 동기화」 버튼이 생김) |
| `FAKE_TODAY` | 테스트용으로 오늘 날짜를 고정 (`2026-11-04` 형식). 실제 운영에서는 쓰지 마세요 |

## 7. 백업과 복원

- 매일 자동 백업: `data/backups/auto-날짜.db` (최근 30개 보관)
- 수동 백업: 교사 화면 → 설정·백업 → 「지금 백업 파일 내려받기」
- 복원: 같은 화면에서 백업 파일을 올린 뒤 **서버를 다시 시작**하면 적용됩니다. 기존 파일은 `data/backups/before-restore-…db`로 따로 보관됩니다.
- 서버를 옮길 때는 `data/library.db` 파일만 복사하면 됩니다.

## 8. 보안

- 학생 QR에는 이름 없이 추측할 수 없는 무작위 토큰(96비트)만 들어 있습니다. 분실 시 「QR 재발급」을 누르면 기존 카드는 바로 쓸 수 없습니다.
- 관리자 비밀번호는 scrypt로 해시 저장, 로그인 시도 횟수 제한.
- 학생·관리자 세션 분리, 학생은 본인 정보만 조회. 다른 학생 이름은 학생 화면에 나오지 않습니다.
- 다른 사이트에서 보낸 쓰기 요청 차단, 쿠키는 HttpOnly·SameSite=Strict(https에서는 Secure).
- 대출·반납·연장·예약·관리자 변경은 누가·언제·무엇을·왜 했는지 모두 「변경 이력」에 남습니다. 관리자 예외 조치(강제 반납, 기한 수정, 예약 취소, 정지 해제)는 사유 입력이 필수입니다.
